# 豆包免费图生视频

在 Codex 内置 Browser 中复用已登录的 [豆包](https://www.doubao.com/chat/) 标签，用该标签的文件上传能力，默认在后台操作。若缺少豆包标签，在同一个内置 Browser 里打开。

如果会话没有显示内置浏览器的快捷控制工具，先查已安装的 Browser 插件。在 node_repl 里使用该插件提供的 browser-client.mjs，保留 setupBrowserRuntime() 返回的运行时，再用 browsers.list() 找 type 为 iab 的浏览器。通过 tabs.list() 和 tabs.get() 复用现有豆包标签，以实际读到页面为连接验证。

标签已经打开而控制工具无法连接时，报告具体故障和提交状态，保留素材和已有任务记录。恢复后接续原标签和任务。外部浏览器或 Windows 前台控制仅在用户另行指定时使用。

1. 先查游戏实际使用的方向、动作和帧规格。像素精灵同时确认单格尺寸、锚点、目标调色板和过滤方式。已有角色用已认可的静帧作为首帧。用 `sprite-gen video-canvas` 准备与动作相符的画布和留白。原生像素图需要放大时，用整数倍最近邻放大并加纯色底，核对上传图与原帧的可见像素一致。绿色或品红按角色颜色选，提示词写同一个色值。
2. 新对话选「视频生成」，在模型菜单核对当前免费档（已跑通 **Seedance 2.0 Mini**），在界面设置画幅、时长等参数；简单循环优先用够截取完整周期的短片。免费额度由账号和界面决定，额度、模型及已在界面设置的规格都不写进生成提示词。以任务卡及实际下载文件为准。若出现参数确认卡，核对后简短确认一次；若已经排队，等待该任务。登录失效、免费额度不足或提示升级时说明页面状态，不切到付费模型。
3. 首张单独上传锁定造型。已有动作参考时，按时间轴导出独立 PNG，按编号从早到晚逐张上传，核对每张缩略图已就绪且顺序一致，再提交。参考视频留在本地抽帧；Spine 从骨骼时间轴取样，记录动作时长和每张图的时间点。关键动作须包含支撑、接触、转折和循环接点。入口限制张数时，优先保留完整动作阶段；用户指定的完整序列按可用入口分段上传。提示词明确首张约束造型，其余按顺序提供动作参考；再写动作、朝向、固定镜头、纯色背景和循环要求。普通循环用一两句，只有动作读不清才补关键姿势或接触点。由引擎移动的角色在画面原地完成动作。例如「灯笼鱼朝右原地游动，尾巴自然左右摆动，幅度适中，鱼头稳定。固定镜头，纯绿背景，动作循环。」日常游动默认自然适中；缩到目标尺寸后看不清时，先确定是原动作、截取还是像素后处理的问题，再调整幅度，避免直接改成夸张动作。
4. 打开完成卡片的播放按钮。在播放器下载 MP4。已超过页面预计时间且任务页没有新卡片时，可以重载已提交的对话，刷新状态。Codex Browser 有媒体下载能力时，使用播放器内的 `video` 元素和 `downloadMedia()`，读取工具返回的下载位置。下载文件名可能重复，按本次下载结果定位。用 ffprobe 核对规格，保留未转码的原片、首帧、提示词和实际模型。
5. 运行 `sprite-gen video-frames --clip <mp4> --out-dir <frames> --key <green|magenta> --reference <first-frame>`。对照同时间点的原视频与透明帧，检查真实 alpha、边缘残色、阴影、水印和动作中的锚点。出现斜像素、色块扭曲或轮廓漂移时，沿原视频、去底帧、导出帧定位最早出现的位置。
6. 用 `sprite-gen video-loop --frames-dir <frames>/keyed --out-dir <loop> --fps <实际帧率> --state <动作类型>` 截循环，记录起始帧、帧数和帧率。自动切错时，从实际视频里找相邻两次同相位的姿势或接触点，按 `--cycle fixed --start <首帧索引> --length <相位间隔>` 重切。
7. 像素精灵需要用最终交付帧验收。按项目的目标格位检查实际尺寸，再用整数倍最近邻放大并排检查轮廓、斜像素、色块、透明边缘和细节。需要重采样时，整段使用同一画布、锚点、采样相位与调色板，并标明这一步是像素后处理。回到实际尺寸播放完整一轮，复查像素步进、帧间闪烁、动作幅度和首尾接缝。原片的动作或造型问题若仍可见，标为候选并说明具体问题。

### 视频选段与动作验收

- 逐帧复现是单独的交付要求。仅在用户要求逐帧临摹或复现时，用指定原帧判定对应姿势、接触点和停留。自由生成的视频以认可造型、动作意图和原生运动连续性验收。动作参考提供走向和应出现的事件，允许视频与原帧有相位、步幅、持械角度和节奏差异。
- 从原片选连续整段。循环记录零基首帧、尾端排除帧、帧数和原生帧率。对着选段前后邻帧核对接缝、支撑和握点，查体型与装备是否在自己的时间轴上跳变。比对网页可以共用播放控制，同时保留视频原速和临摹的原帧停留。

### 像素网格处理

- `video-frames` 和 `video-loop` 负责去底和截循环。`pixel_unfake` 是 [A 路线的图集行提取选项](pixel-unfake.md)，B 路线不会自动执行它。
- 已符合目标网格的帧可以直接验收。高分辨率视频出现半格或歪斜色块时，以确认过的原帧和实际格位确定整段共用的采样网格。整段使用相同的缩放、采样起点和调色板，保留动作位移。按项目要求处理透明度。
- [PerfectPixel 适配器](../../pixel-game-reskin/references/tools.md#可选固定网格整理)可整理已有完整格位的高分辨率单帧。用于序列时先确认整段采样与锚点一致。逐帧自动找边界或重新居中容易引入抖动。网格整理后还有局部轮廓、符纸或纹理闪烁时，用[原生像素局部修补](../../pixel-game-reskin/references/generation-and-pixels.md#原生像素与批量稳定)。动作或造型明显走样时回到原片，调整参考或重拍。

交付时从实际输出核对首帧与原片、透明帧与截循环记录，以及最终预览的尺寸、帧率和验收结果。与旧版对照时用同朝向、同尺度、同底色的并排循环，保留各自播放速度并标明帧数。预览来自最终要评审的那组帧。若要求接入引擎，核对场景实际引用的素材与预览是否一致，并报告运行验证情况。
