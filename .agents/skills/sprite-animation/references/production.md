# 透明、对齐与后台导出

## 先识别背景，再处理

读取文件模式和 alpha 实际值，而不是从棋盘格外观判断透明。已有正确 alpha 就保留，不要先转 RGB 丢失通道。RGB 棋盘格是生成器可能返回的结果，即便提示词要求了透明。

对浅色中性背景，可在候选颜色掩膜上从边界做连通填充，仅清除与背景连接的区域。候选阈值由当前图取样决定。兽人案例使用过最小 RGB > 155 且最大通道差 < 28；这是案例参数，不能照搬到其他画风或衣服颜色。

保留暗轮廓内部的白发、刀刃等浅色物体。手臂与躯干之间、腿间、头带与头发之间可能存在封闭背景洞，必须看图后设置种子，不按亮度全局删除。轮廓不闭合导致抠图侵入角色时，应修正掩膜或使用更合适的提取方式，而不是接受受损角色。至少在深、浅两种纯色底上查看成品，检查洞隙、白边、孤点和细刀尖。

游戏用透明 PNG 与展示 GIF 分开。GIF 支持有限的透明索引，但此流程默认用纯色底便于查看动作；不要暗示它是带完整 alpha 的 PNG 替代品。若用户要求透明动画，再明确输出支持及视觉限制。

## 整帧对齐与像素规范

同方向序列图需要先验证网格中的完整人物数量。剑尖可能越过网格线进入空白间隙，机械等分裁切会切断武器；可用前景连通区域识别完整人物后分配到网格位置。若人物或武器实际重叠，不能靠此方法分离，需重画或人工处理。洋红抠图后还应检查暗轮廓的紫边，处理受背景污染的边缘色；保留角色真实的红色服饰。

- 保留一张原始图对应一个姿势，规范化参数单独记录：缩放比例、源身体定位点、源脚底、目标锚点、背景掩膜参数。
- 以身体尺度和支撑关系做等比缩放，不以“人物加刀”的总包围盒定尺寸。可用腰到脚底距离、头身比例交叉比较；下蹲或透视变化时不能硬性锁死投影骨长。
- 整帧统一平移对齐到固定画布，运动重心与脚步应保留。站定阶段检查支撑脚稳定，跨步阶段不能强行固定所有脚像素。不能靠拉伸小臂修复原画。
- 刀尖可能低于脚底，不能把前景包围盒底部直接当作地面。使用看图确认的脚底或支撑点。多方向身体高度需交叉核对，不因某张图留边更少就把该方向画得更大。
- 俯视镜头下，前后脚在屏幕上通常有高度差，不把两脚压到同一水平线。原地双脚站立动作可用两个地面接触点之间的位置作为锚点；迈步或跃起时按实际支撑/地面轨迹处理，不能逐帧自动锁定双脚中点。颜色识别只能提出候选点，必须检查远脚遮挡、皮肤碎片和误选手部的情况。
- 区分固定游戏锚点（画布中放置角色的坐标）与制作时用来校准的身体/支撑标记。鞋底不是通用根骨；骨盆也不能每帧锁死。跳跃、下蹲和迈步必须保留相对根位置的运动轨迹。站定动作可用鞋底接触校准，但要排除鞋带/阴影切碎皮肤、小腿进入检测区等干扰。
- 缩放采用最近邻、统一逻辑像素网格，禁止每帧独立自动裁切居中。先确认透明轮廓完整，再收集所有帧的不透明色样形成共同调色板，通常可从 48–96 色尝试，按风格决定。不让透明 RGB 背景主导颜色统计，禁用抖色避免额外噪点。
- 每帧 alpha 与画布保持一致规范。硬边像素风通常二值化 alpha；若用户选择半透明效果，保留相应 alpha 并调整验收规则。

## 组装清单

创建项目中的 JSON（例如 `motion.json`），文件路径相对于清单所在目录。PNG 必须已经是完整、透明、对齐好的整帧；输出目录应预先存在。不要覆盖用户未授权替换的工程。

```json
{
  "canvas": [256, 256],
  "tag": "attack",
  "output": "attack.aseprite",
  "frames": [
    {"image": "poses/ready.png", "duration_ms": 400},
    {"image": "poses/windup.png", "duration_ms": 180},
    {"image": "poses/cut.png", "duration_ms": 100}
  ]
}
```

这是格式示例，三张姿势不保证足以表现完整攻击。时长使用正数且为 10 ms 倍数，避免 GIF 时间量化改变节奏。画布、时长和动作名均不固定。

通过已安装的 CLI 运行；下列路径用实际项目与 skill 路径替换，不是要求创建这些目录：

```sh
aseprite -b --script-param manifest=/project/motion.json --script /skill/sprite-animation/scripts/assemble.lua
aseprite -b --list-tags --list-layers /project/attack.aseprite --sheet-type rows --sheet-columns 4 --sheet /project/attack-sheet.png --format json-array --data /project/attack.json
```

`-b` 是无窗口批处理。无需打开 Aseprite GUI，也无需桌面自动化。用 `aseprite --help` 核对本机能力；如脚本或批处理不可用，按当前环境处理，不静默弹出窗口。安装或升级沿用用户授权和系统要求。

## 从实际导出制作预览与核验

用 Pillow 按 Aseprite JSON 中的矩形切出帧，按相同 JSON 的时长制成 GIF，整数倍最近邻放大。正常与慢放版本共享同一组画面；慢放可统一放慢，或明确标为逐帧检查并设置最短停留时间。保存无限循环及正确 disposal，避免透明帧残影。

核对清单：

1. 原生工程重开导出的每帧尺寸、帧顺序、动作标签、时长与清单匹配。
2. 可见像素和 alpha 与规范化源 PNG 匹配；Aseprite 可能清空完全透明像素下的 RGB，这不构成视觉差异。
3. 人物、武器不触边裁断；PNG 真实透明，内部洞隙和细节目视完整。单独检查 alpha 取值不足以证明抠图正确。
4. 两份 GIF 全部解码，核对循环和实际画面时长。重复帧被合并时按连续画面持续时间核对；检查返回准备姿势是否跳变。
   出现“像多播一次”的反馈时，逐张匹配解码画面与源帧，核对实际顺序及各画面持续时间，不能只查总时长。若顺序一致，检查原画运动轨迹是否反向、重复蓄力、提前收刀或收势未完成。循环首尾相同仍需检查倒数第二帧→末帧→首帧→第二帧；支撑点稳定也不证明躯干姿势衔接平滑。
5. 查看关键姿势对照图及手部/脚部细节；区分文件检查通过与动作自然度通过。默认用无特效版本审阅。

记录每张原画提示词、引用的参考图、规范化参数、输出规格与仍存在的漂移。保留可重新制作的源图；清理临时检查图及本轮辅助进程。最终链接清楚标记 GIF 为展示预览、PNG 为透明游戏素材。
