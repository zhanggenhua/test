# 完整人物精灵动画

把完整人物动作原画制作成可编辑的逐帧精灵动画。此流程不建立实际骨骼绑定，也不进行物理仿真。动作自然度来自姿势设计与整个人物重绘；程序负责可重复的素材处理。

已有游戏的换皮先用 `pixel-game-reskin` 判定。体态与运动方式相近且保留原动作时，按实际素材结构换静态图、部件、attachment 或逐帧原画。新旧角色体态、支撑关系或运动方式差异大时，设计符合新角色的动作；走视频转循环时用 `sprite-gen`，逐姿势制作时用本技能。

分件/骨骼的原动画可以组装成 GIF 供对照，须标为预览，不能将其改装成新的逐帧运行素材。少量姿势或流程检查不证明连续动画、人物结构与事件时机已匹配。

## 工作流

1. **固定镜头、造型与规格。** 优先使用用户已认可的角色图，分别记录相机俯仰角/投影方式与人物朝向；45°俯视不是水平旋转45°，多方向只变朝向，不变镜头。缺少镜头信息且会影响素材用途时，先用具体母版确认或说明假设，再大量生成。记录头身比、服装、武器尺寸和握法。区分人物本体像素高度与动画画布尺寸：例如本体约160像素，举刀时可能需要更大画布。按动作留边，不把每张含武器包围盒缩到同样大小。
2. **设计关键姿势。** 把动作分为可读的受力阶段，例如准备、蓄力、挥击、落点、收势。按需要增加过渡，不固定角色、分辨率或帧数。先画关键姿势，再补承接画面；不靠大量重复帧假装动作更细。
3. **生成完整绘图。** 使用可用的 imagegen skill 和内置生成工具。生成前查看参考；以认可造型为身份基准，邻接姿势为运动参考。结构探索时每次画一个完整姿势；动作已认可、需要补足连续帧时，也可把同一方向的完整人物姿势放进一张规则序列图共同生成，随后检查帧数、方向与比例。提示词明确脚部支撑、躯干转动、两臂连接和握柄关系；见 [动作提示词](references/pose-prompts.md)。不把旋转切出来的上臂/前臂当作复杂攻击的默认解法。围巾、眨眼等局部动画和用户指定的骨骼流程可以使用其他合适方法。
4. **审阅完整动作。** 先看肩→上臂→肘→前臂→腕→握柄是否连续，遮挡、拇指方向、武器接触和脚部支撑是否合理。关节不必全部露出。再看相邻帧的脸形、衣服、武器长度与手的位置是否漂移。结构错误时重画对应的整个人物姿势；不要一轮轮扭曲小臂去凑握点。邻接参考会累积漂移，必要时重新加入认可造型。小范围尝试未改善时改变姿势或参考策略，并说明未解决处。
5. **确定性后处理。** Pillow 处理实际透明度、整帧等比缩放和平移、统一调色板、最近邻输出。关节位置/抠图种子是每个角色的配置，不能沿用上一角色坐标。保留原始绘图，避免覆盖认可素材。详细方法见 [透明、对齐与导出](references/production.md)。
6. **后台组装与验收。** 用 Aseprite 的 `-b` 批处理保存 `.aseprite`，再重开并导出 PNG 图集、JSON；Pillow 读取实际导出生成正常速度和无特效慢放 GIF、关键姿势对照图。使用 [打包清单](references/production.md#组装清单)及 `scripts/assemble.lua`。默认不启动 GUI、不操作用户桌面。按用户要求通过 GIF 审阅，已有授权内继续工作，不为每个阶段重复要求批准。

## 交付标准

- 原图若没有 alpha，或棋盘格画进 RGB，不能称为透明素材。PNG 单帧/图集必须检查 alpha，展示用 GIF 是否带底色要明确。避免把钢刀和白发误抠掉；有 alpha 也不代表洞隙和边缘正确。
- 数学握点约束、导出像素一致、GIF 解码通过，均不证明人体结构合理。实际查看关键姿势和手臂细节；若无法连续观看动画，说明只做了逐帧视觉检查及文件验证，由用户看 GIF 验收。
- 单独审阅帧间体积：对照头部、躯干、肩臂厚度、骨盆和双脚。出现忽大忽小时，沿原始绘图→规范化PNG→实际导出定位问题。脚等部位稳定而上身膨胀时，属于局部形体漂移，不能把整帧缩小当作正确修复；重画完整姿势。仅在确认全身等比例漂移后才使用整帧缩放校准。投影面积变化只作为审阅线索，不作自动归一化公式。
- 默认先提供无特效动作。添加刀光等效果时保留无特效版本，方便检查人体与接触位置。
- 导出与输入逐帧核对可见像素、alpha、时长、标签、完整边界；GIF 核对解码后时间轴和循环。帧间存在相同画面时编码器可能合并，按实际画面持续时间核对，别只数 GIF 帧。
- 交付正常 GIF、慢放 GIF、透明图集、JSON、原生工程，以及生成提示词和处理参数。不要把高分辨率效果图或合成预览当成实际游戏精灵。已有项目只保留必要的新资产与生成工具，保持未授权修改的角色素材原样。
- 修改已有逐帧动作时，在聊天中内联展示“原版 / 新版”同步 GIF 或用户要求的逐帧对照，保持同阶段、镜头、尺度和背景，不只展示新形象或给链接。分件换皮按 pixel-game-reskin 交付静态部件及原曲线组装预览，不强制生成逐帧素材；无需为交付对照默认打开游戏。
- 用户指定对比快捷键时，检查已有按键冲突并接入切换；切换只改变外观，保留当前位置、动作进度和玩法状态。未要求快捷键时不默认增加这类功能。

## 工具与复用边界

ImageGen 画动作，Pillow 处理图片和 GIF，Aseprite 管理可编辑时间轴及游戏图集。复用本机可用 CLI，不因为缺少视频编码器去修复无关环境。脚本不会自动修正人体，也不会从一张立绘自动推导所有动作；原画审阅与针对性重画仍是流程的一部分。

`scripts/assemble.lua` 是从实际通过的组装流程提取的通用单层工具，接受任意动作名、画布和整帧 PNG。需要多层特效时依据项目扩展，不硬套单层格式。修改脚本后运行 `python3 scripts/test_assemble.py`；它使用临时目录和真实 Aseprite CLI，不打开窗口。
