# 实时 shader 验收

- 从参考帧确定值得实时计算的部分。例如元气弹的球面折射与内流、连续变化的爆发光壳可以交给片元 shader。角色、事件时序、命中点、镜头和已有粒子可以继续由原时间轴驱动。若使用专用 shader 的项目尚未授权接入，先在同一独立网页验收。
- 网页保留可切换的同帧基线。对照时共用角色素材、相位、球体轨迹、靶点、距离、画幅和背景。按参考观察球缘、亮芯和爆发体积，再测镜像、透明底、近远距离、未命中和终帧归零。
- WebGL 2 可用透明渲染层叠合现有画面。若使用预乘 alpha，片元颜色输出 `rgb * a`、透明度为 `a`，使用与之匹配的混合方式。按需限制实际绘制区域，避免为局部特效覆写整张视口。Shader 的时间由预览统一提供，暂停和跳帧时仍能得到对应画面。
- 交付前在目标浏览器实际编译、播放并核对渲染器。区分硬件渲染、软件 WebGL 与 Canvas 回退。回退画面要标出实际使用的路径。需要性能结论时，再在同尺寸、同帧、同视觉范围测量。
- 交付称为 3D 的版本时，写清各层实际用了空间网格、体积采样还是屏幕投影。网页提供独立的侧视检查，默认与成品共用渲染器、资产、目标机位和时间。用可转的检查视图或实际网格线框核对体积，成品镜头保持游戏机位。

- 球体爆发的内核要能从实际游戏机位读出前后层。若主要亮流只是沿网格表面收拢，参考中的内部遮挡、旋流和体积光会在侧视压成一条纹路。先确认教程如何在内部采样和合成，再按关卡深度裁剪，并分别核对暗壳、亮核和前景碎片。[体积爆炸实例](https://www.jd.swardson.com/projects/raymarched-explosion.html)
- 同步对照页把共用进度条放在画面上方。拖动暂停并更新两侧。窄窗中保持进度条可见，原片和成片均用完整视口，默认相位配对沿用已确认的版本。
