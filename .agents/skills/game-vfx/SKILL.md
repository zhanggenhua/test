# 2D 游戏特效

## 先看参考，再找现成方案

- 打开用户提供的素材和现效。只有特效任务时，沿用现有角色与动画进行合成预览。有指定招式或视频参考时，先完成下面的选帧流程，再开始制作。
- 查项目可复用的原始资源、已安装 skill 和公共资源。按具体动作、风格、引擎、输入输出分别检索，例如 `beam sprite sheet CC0`、`pixel art effects generator export transparent PNG`、`Godot 2D beam VFX GitHub`。仓库可能是素材库、导出器或引擎移植，检查 README、目录索引以及 `skills/**/SKILL.md`，并顺着上游、移植和调用方查找。只看到仓库描述时标注为候选。
- 有匹配的现成方案时，按上游 skill 或制作指南跑原始样例。用原工具导出一份透明小样，保留原始参数和帧时序作为基线。按游戏里的显示尺寸合成角色与背景，检查首发、持续和收尾，再决定要改哪些地方。pixelfx 等工具的试跑入口见 [sources.md](references/sources.md)。
- 基线已符合需求时直接复用，按需改色、挂点或事件时序。需要改画风或运动时，从基线的可见差距入手，保留前后样片并逐轮渲染检查。用户要做素材或验证流程时，先在独立预览中跑通制作与验收。根据任务范围决定是否接入项目。
- 确认成品时记录预览入口、版本标识和关键阶段的全幅帧。收到“改回上一版”时，先用截图、同阶段历史帧或新增参考的时间线找对版本，逐项核对要恢复的是出球、命中还是余波。优先复用对应源码或资产，把已验收的其他部分接回去。对于确定性渲染，可以逐像素核对涉及范围以外的关键帧。
- 引用或交付外部素材时核对对应文件的授权和署名，区分工具、图集、字体等来源。记录原始链接、素材版本或提交号、参数、改动与验证范围。把资料阅读、独立导出、引擎预览和画面验收分别写清楚。

## 动态参考与选帧

- 把找参考交给子代理时，先指定这段要解决的动作、人物和装备。采集者自己原速看完候选，步进核对起手、关键接触和收势，标出切镜、遮挡、缺拍与可辨的握点。按用途选出最适合的连续片段，交原片起止、全幅关键帧、采用理由及更弱候选的淘汰理由；仅有场景或特写的来源只能用于其可见要素。主任务复看入选段与证据帧后再制作，避免重复遍历候选。没有完整镜头时标明可用动作范围与另行编排的部分。
- 用户指定视频时直接定位原段。需要自行找招式、角色动作或特效参考时，先到 [Tenor](https://tenor.com/) 搜现成的 GIF。用作品名、角色、招式的英文或罗马字组合要看的阶段，例如 `Kid Buu Genkidama throw`。打开动图实际播放，核对动画、游戏或二创来源，以及是否覆盖要看的动作。找不到关键阶段、片段不连贯或需要确认原始时序时，继续找动画原片或同类游戏实机；来源按用户指定的版本选。
- 找释放过程时，从出手前一拍看到能量第一次脱离挂点并向目标移动。球和投射体核对预备姿势、发力、离手、前进，束状特效核对起点和首次展开。记录每个实际可见的节点。托球、飞行中段或爆炸单独出现时，只能作为对应阶段的参考。
- 先看完整段，再在阶段交界连续逐帧核对。选出启动、首次出现、分段变化、成形、受击和回落中实际可见的节点。留下原片链接、时间码或帧号、当帧可见证据和缺帧区间。原片切镜、遮挡或拖放精度不足时，明确哪些是估计，无法判断时保留未知。
- 制作前用选帧确定挂点、遮挡关系、轮廓、主次运动和节奏。在同一参考镜头里量相对角色的尺度。目标机位与原片不同时，单独记下为目标画幅重排的尺寸、间隔和时长，便于复查哪些来自原片观察。
- 遇到特效出画，逐段标明镜头拍到的范围，沿连续原帧记录前缘在哪条画边进出、交点如何移动、人物和场地何时被遮住或重新露出。需要重建全貌时，先找同一版本、同一招式的远景、自由机位或相邻镜头；可用其他演出的同一招式补足造型依据，注明作品、时间码和采用部位。
- 找不到完整机位也要完成重构。把原片约束与推测分别记录，用局部曲率、遮挡、发光层次和各部分的运动推定主体、背侧与地面接触，建立能从头到尾独立成立的完整效果。包围形状可用来确定尺寸，最终形态还要表现内部能量传播、层间遮挡、轮廓变形和解体等参考中可见的行为。
- 交付时让用户能直接看已验证的原片段和实际用到的全幅选帧。逐张提供原图链接、时间码或帧号，以及参考的轮廓、遮挡、触点或节奏。标明哪些图片实际上传给生成工具，哪些用于分析后转写提示词。把对应阶段放进同一组可慢放或步进的对照。原片多机位时按阶段对应并标注切镜，项目内新旧版锁定镜头、角色和显示尺度。

## 按目标画风改造

- 对照页按用途标出原片、第二参考和自制版本。原片指目标作品、目标招式的源画面，保留为默认项。跨作品画面即使用来拆解命中、余波或材质，也标为第二参考。切换候选或适配 2D 时沿用这两项的身份和顺序，独立 3D、旧版和技术检查供手动选择。交付前实际打开入口确认默认原片，并拖到当前阶段核对画面与时码。
- 先给每份参考标明用途。指定作品的招式以该作品的关键动作、受力和消散方式为主参考，网页默认与它对照。跨作品参考只取用户指明的造型或分层，例如球壳亮纹、前后遮挡、碎石密度；引入另一招的驻留、爆炸形态或收尾前，须有招式本身的依据。只有成球、刀光或火焰等单一造型的片段，采纳其材质和内部运动。左侧始终用完整招式验收。
- 参考只改某个阶段时，先用实际时码列出采用的视觉层和已确认的层。排查截图里的变形或亮线时，用同机位逐层开关区分顶点形变、表面流纹、辉光和独立光条。改亮度先定位发光和后处理，修轮廓先定位网格和透明遮罩。先看峰值，再看进入与退出的邻帧，确认效果没有延续到错误阶段。
- 复杂爆发允许用球、圆环或锥体搭建空间骨架。若最终游戏尺寸只能读出这些简单几何，验收退回。用原片的峰值及回落帧，逐一指出前层遮住哪一层、哪里有空隙、哪一层先破散或回卷，再按原速复看。发光过曝时还要检查下一张可辨内部结构的原帧。

- 调色只改色阶与色温。需要风格化时，从用户参考提取轮廓、边缘处理、明暗分层、粒子形状和运动节奏，挑出对识别度影响最大的几项。注明每版具体改了什么。
- 源素材为低分辨率像素风、目标为平滑火柴人时，检查放大后的网格、抖色边和辉光。可沿用原来的动画结构，用目标分辨率重绘干净的亮芯和切面，统一抗锯齿、外沿宽度、碎光形状以及过渡时长。按游戏内尺寸对比源基线和改造版，有争议时加一份仅换色的对照。

## 有作者工程时先复现原场景

- 将作者工程或资源包保留为只读，在独立工程中恢复源场景。核对原视频和随包 Demo 各自包含的角色、机位、阶段和包外依赖。沿场景实例追到实际启用的 Prefab、发射器、Renderer、网格或面片、材质、shader、贴图与后处理。先记录真实的机位、FOV、尺度、挂点和裁边。
- 分开读粒子时序和绘制顺序。记录 Burst、寿命、速度、尺寸及自定义数据曲线，跟到 shader 实际使用的顶点通道、贴图采样、裁剪、混合、深度和排序。核对 HDR、Bloom 与颜色空间。黑色遮挡、亮芯、口环、尾丝等难辨层用同一全幅机位做逐层开关验证，确认各自在哪些阶段出现及怎样消失。
- 用源场景的原机位播放整段，按事件对齐原片与独立 3D 候选，再步进检查关键交接。先验证网格、材质、发射时序和后处理，再为游戏的 2D 机位重投影和对齐挂点。注明哪些来自源配置、哪些已经引擎实跑。缺许可证、依赖或原镜头时，写明受阻项目，并保留全幅视频帧作为画面对照。

- 原场景跑通后，若移植的质感仍有差距，保留真实网格、UV、粒子顶点色和材质使用的自定义数据，核对原贴图的滚动、裁剪、混合、软深度和 HDR Bloom。逐帧核对可用原引擎导出的网格样本，明确哪些是原引擎采样，哪些由目标端实时绘制。同步比较蓄力、展开、峰值与退场，先定位边缘、发光或裁剪在哪一层丢失，再调整该层。

## 3D 特效用于 2D 横版

- 用户指定先做 3D 时，先在独立三维场景制作和验收，用可调透视机位、网格地面和尺度占位物。即使只有视频，也按参考的斜俯或侧面机位估计构图，在同一时间轴核对成形、前后遮挡、亮度层次与消散，并在另一个机位复核体积。该阶段的交付是完整 3D 预览。进入横版适配阶段后再重投影和对齐游戏挂点。

- 开做前锁定目标的固定侧视机位、角色比例、朝向、画布和地面基线。3D 模型、粒子、材质或体积只负责效果自身的空间结构。来自斜视、俯视、追拍的参考保留原机位供分析深度、遮挡和时序，成片按目标侧视重新投影。
- 光束和投射先标出掌心或武器口、目标受击点和出画边界。水平攻击用同一出射高度。斜射必须来自真实的技能方向或两个端点的高度差。束身可在发射口展开，维持段的截面由效果设计和游戏距离决定，禁止把参考镜头引起的远端放大、下坠、透视缩短或斜视口环套进成片。
- 对照沿景深前进的参考时，先区分物体真实尺寸、摄像机投影和画内尺寸。世界半径在 3D 场景保持设计值，先跨机位检查投影，再用游戏固定横版机位重投影。只有蓄力、受压、破裂等招式自身事件驱动尺寸变化。横版首尾都用同一地面轴和角色比例核对球径。
- 换成横版机位时，重新计算朝向相机的面片与沿速度拉伸的粒子。如果用网格样本，按目标侧视重新烘焙这两类粒子，同时沿用原材质和生命周期。同一画布里用真实掌心、目标与地面坐标验收。混合场景中的 2D 角色可用透明轮廓写入深度，让特效前后层按实际遮挡合成。
- 成片根据项目机位和用户确认的镜头选择透视或正交。龟波气功网页用透视侧视，锁定掌心出射和横版作用轴。3D 内部照常计算前后遮挡、环绕、碎片速度和崩解。地面冲击、投影和接触光以项目地面基准定位。最终验收全幅的起手、飞行、首触、峰值、退场，逐阶段检查手部挂点、目标、地面和屏边。参考机位的画幅用于核对构造和运动。

## 让视觉时序与实际挂点对齐

- 从真实的技能事件或动画取出手、激活、命中和结束时机。划定需要交付的部件，记录它们定位所需的画布、像素比例、锚点、朝向、透明与混合方式。帧序列保持一致的坐标系并记录逐帧时长。分层输出时保留可复用的独立透明资源。
- 多层特效分别确定出现顺序与绘制顺序。每处重叠明确哪一层遮住哪一层。把触地类效果的触发点对到手、脚或物体首次接触地面的帧，在合成画面核对接触后才出现的尘土、裂地等反馈。
- 投射体在受压中膨胀或破裂时，以首触前、首触、压入后的同一侧轮廓追踪中心、投影半径与着力点。爆面继承飞行主体的状态。若交接帧同时读出互相无关的两团能量，回到挂点和时序修正。
- 飞行物按实际轨迹决定命中、出画和触地。例如同时设计平射和落剑时，分别检查命中与落空，落剑的剑尖从上方触地后才出现插地与召回状态。同一件武器跨阶段保留已定的轮廓和材质，把拖尾与命中光单独绘制。
- 先确认主体轮廓、亮度层次和运动方向。用蓄力、释放、持续、回落中合适的阶段安排时序，控制细碎粒子的数量和亮度，让它们支持主体。按角色和地图的实际大小回看，避免特效吞没出手动作。
- 即时制追踪投射体在模拟步读取目标最新位置和碰撞体。首触、触地、引爆取自模拟事件。近距先命中时直接进入爆发，远距先触地才按实际地面轨迹生成尘道。固定时间码用于回放对照。用近距、远距、移动目标及失去目标验收同一实现。
- 固定形状和距离可做透明帧序列。射程或命中点会变化时，把相关位置交给引擎参数，优先保留两端尺寸和中段的运动细节。激光、能量波见 [beam.md](references/beam.md)。
- 球壳、能量流、扭曲或连续变化的光体需要逐像素表现时，可先在独立网页比较 shader 与现有效果。用 [实时 shader 验收](references/realtime-shader.md) 核对分层、透明合成与实际渲染路径。

## 用同一画面对比

- 此用户的游戏特效只交付完整游戏视口。预览默认从起手原速播放整招，比较方案时保留角色、目标、舞台与完整镜头。按“神似”验收时看聚势、出手、命中和场地反馈在游戏尺寸下是否读得清。内部诊断用的局部放大图不进入预览、交付或验收。

- 统一预览按明确的版本标识选择当前成品。已有横版 2D 和独立 3D 时，在同页提供可见的切换入口，历史版本从版本菜单可选。交付时直接打开用户使用的默认链接，核对选中版本、实际渲染路径与参考配对。本地素材缺失触发回退时，页面标出实际加载的版本。
- 比较材质时锁定角色帧、出手点、目标距离、镜头、背景和画布比例。比较整招演出时注明各版站位与时长，用同步播放和可步进的关键帧覆盖蓄力、首发、持续、收尾。
- 重构全貌时，先在目标固定机位的完整视口核对主体、远侧和接地点。用独立的参考视图核对该机位下的入画、最大覆盖、裂解和退出，并记录两个视图各自的依据。用目标机位确定成片的轮廓和裁边。
- 原速检查节奏、打击感和收尾。慢速逐帧检查轮廓跳变、出手点漂移、随机噪点、裁边、闪帧和透明边缘。可变效果另测近、远、移动端点和未命中。有反向施放的效果，在相同阶段核对正反向的挂点和遮挡。
- 给出哪版更适合当前参考以及可见原因。交付可播放预览和项目所需的源文件或透明帧序列，注明实测路径及仍待引擎或实机确认的项目。
